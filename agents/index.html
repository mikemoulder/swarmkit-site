Build a procurement agent

Give each agent a bounded role, then let the coordinator and settlement policy enforce the market rules.

Give the agent one role

A buyer strategy turns application demand into a quantity and a budget. A seller strategy quotes a price and available capacity. The coordinator owns deadlines and clearing.

const buyer = {
  id: "research-agent",
  demand: () => ({ quantity: "3", budget: "15" }),
};

const seller = {
  id: "inference-seller",
  offer: () => ({ capacity: "5", unitPrice: "4" }),
};

Pass these strategies to simulateProcurement. For live participation, authenticate the caller before mapping its identity to a RoundCommand.

Keep approvals with the buyer

  1. Derive and review a closed settlement plan. Resolve the buyer’s trusted public key outside the agent’s input.
  2. Set the round, asset, transport scope, seller allowlist, cumulative maximum and expiry in SpendingPolicy.
  3. Sign spendingPolicyMessage(policy) with the buyer’s Ed25519 approval key.
  4. Use executeWithSpendingPolicies with the same journal across attempts. Implement atomic bindPlan for split fulfillment.
  5. Inspect the existing hash after an ambiguous send. Authorize a replacement only after reconciling the original transaction.

Connect NEAR Intents

The buyer must hold a supported asset in the Verifier and have a recognized signing key. Supply a NEP-413 callback for the exact request and a separate relayer callback for the resulting Verifier call. Configure the transport for the asset in the plan.

Test agent behavior with deterministic strategies first. Keep signing and RPC access on your backend. A read-only receipt view can remain public.
